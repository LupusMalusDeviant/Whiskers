# Utils

Small, dependency-free helpers used across the app.

## Files

| File | Purpose |
|---|---|
| `SecretRedactor.cs` | Redacts secrets (tokens, keys, passwords, SQL password literals such as `PASSWORD '…'` / `IDENTIFIED BY …`) from command output and logs before they are displayed or stored; `RedactJson` redacts a JSON document value by value (decoded), as approval cards store it. Capability URLs (Telegram bot token, Discord/Slack/Mattermost webhook keys) and every value in `KnownSecrets` become `***` (R1-25). A pattern that times out withholds the whole text (fail closed). |
| `KnownSecrets.cs` | The secrets Whiskers holds for outbound channels (bot tokens, webhook and ntfy topic URLs, access tokens, SMTP password, signing secret), registered when their settings are bound; `SecretRedactor` replaces each occurrence, longest first (R1-25). A URL is also registered in its normalized, unescaped and user-info-free forms, a capability-like ntfy topic on its own. Values under 8 characters are ignored; at most 256 are kept. |
| `RedactingLoggerFactory.cs` | Stands in front of the logger factory (R1-25, INV-51): the message, each structured value, the template, the scopes and the exception text (`RedactedException`) reach the providers redacted; an entry that cannot be redacted is written as `<log entry withheld: redaction failed>`, never raw. Every enabled entry runs the full pattern set, so a pattern timeout on a loaded host shows that text as `***`. The message is rebuilt from the raw template's holes and the redacted values (never formatted from the raw state; a template whose holes do not match its values is withheld); a value logged under a secret's name (`{Password}`, `{ApiKey}`) is `***` whatever it looks like; a list or dictionary value reaches the providers as one redacted string, its pairs as `key=value`, and the exception they see is a `RedactedException` (the original type name stays in its text; inner exception, `HResult` and `Data` are not passed on). Wired by `Startup/WhiskersLoggingExtensions`. |
| `SinkRedaction.cs` | What every persistent sink stores (R1-24, INV-51): `Text` (URL user info removed, then `SecretRedactor`), `Json` (value by value), `Arguments` (tool/mutation arguments: free-text payloads — `IsPayload`, matched on every spelling of the name — keep only their length, a secret-named key is `***` at any depth). Idempotent; never a prefix of a secret. |
| `ShellUtils.cs` | Shell helpers: POSIX single-quoting of values spliced into host commands. Quoting protects against the shell only — it does not stop option injection (a quoted `-oProxyCommand=…` still reaches the program as an option); operands are also checked by `CommandOperands`. |
| `CommandOperands.cs` | R1-42 (INV-41): the one validator for values that become operands of host commands — git branch (`IsSafeGitRef`), SSH user/host/port (`SshDestination`), nginx site name, container reference, database name on every database path — listings, query, dump, import and the dump's host file name (`RequireDatabaseName`, INV-19: mongosh would run a positional `--eval=…`, pg_dump take `--file=…`, a `/` would put a root-written dump outside the backup directory; for MongoDB also no `.`). Allow-lists that never admit a leading `-` or whitespace (`..` is refused for branches, hosts and site names; an SSH user or a container name may contain it, as ssh and Docker allow); a refusal is an `UnsafeOperandException` (an `ArgumentException` naming the field). Used where the commands are built (executor, tunnel, terminal, git deploy, nginx, database exec), not only in the UI; the builders also put positional operands after `--`. |
| `SecretEnvironment.cs` | R1-43: the environment variables that carry a VPN key (`Vpn__Tailscale__AuthKey`, `Vpn__Netbird__SetupKey`, `TAILSCALE_AUTHKEY`, `NETBIRD_SETUP_KEY`, `TS_AUTHKEY`, `NB_SETUP_KEY`; any case, `__` or `:`, also behind the `DOTNET_` / `ASPNETCORE_` prefixes the configuration reads (`ConfigurationPrefixes`, in the order they win: `DOTNET_` beats `ASPNETCORE_`, a bare name beats both — measured on the real builder) — the test derives them from the real `WebApplication.CreateBuilder` sources and fails on a prefix this list misses). `RemoveFromProcess` (.NET's copy of the environment, which every `Process` start uses; the native `environ` is unchanged) drops them from Whiskers' environment once the configuration has read them (Program.cs); `Scrub` removes them from every `ProcessStartInfo` Whiskers builds — the VPN runner, host commands, SSH tunnels, terminals, the PostgreSQL tools and the Claude CLI (`SecretEnvironmentTests` fails a process start that does not, and any `Process.Start` handed something other than a start-info variable). Neither changes the block `/proc/<whiskers-pid>/environ` shows: `entrypoint.sh` moves the keys into a file before Whiskers starts. |
| `ExecutionTimeout.cs` | R1-57 (INV-40): `IsUsable` — whether a host command's timeout is a real deadline (positive and within what `CancelAfter` accepts). The mTLS host shell and the local/SSH executor refuse anything else before a command starts. |
| `MarkdownSanitizer.cs` | Post-filters rendered (LLM) markdown HTML, rewriting any non-`http(s)`/`mailto`/`#` href to `#` so a model-supplied `javascript:` link can't become a live one-click XSS. |
| `EnvMasking.cs` | Decides whether a container env-var value should be masked in the UI — a sensitive key OR a value with inline credentials (`://user:pass@`). |
| `ForwardedHeadersConfig.cs` | Resolves the trusted proxy networks for the ForwardedHeaders middleware (`ForwardedHeaders:TrustedNetworks`, CIDRs or single addresses). R1-50: an empty list means loopback only (never trust-all); an entry that is not a canonical CIDR or address (`172.18.0`, `10` and `0x…` are refused) throws, which stops the start; `FromConfiguration` reads the indexed entries or one comma-separated value. A CIDR with host bits set, a prefix with leading zeros and an entry without a value (a nested object) are refused too, each with the reason. `RefuseFrameworkTrustAll` stops the start when `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` (the framework would trust every peer ahead of the pipeline). `IsTrusted` judges a peer the way the middleware does (an IPv4-mapped peer matches networks of either form); `IgnoredItemKey` marks a request whose forwarded headers were ignored, which the Auth:Disabled gate refuses. |
| `ForwardedHeadersObserver.cs` | R1-50: the peers whose forwarded headers were ignored because they are not trusted proxies (up to 8 distinct ones, each for 24 h after it was last seen); the production-readiness check names them (a proxy still to be listed, or a spoofing client). |
| `PrometheusText.cs` | R1-41: text for the Prometheus exposition — `Label` escapes a label value exactly as the format requires (backslash, double quote, line feed; a carriage return is left as it is, so distinct names stay distinct), `Comment` cuts a comment at its first line break, so a name cannot break the output or forge a series. |
| `MetricsScrapeAuth.cs` | Constant-time bearer-token gate for the Prometheus `/metrics` endpoint; disabled (opt-in) when no scrape token is configured. |
