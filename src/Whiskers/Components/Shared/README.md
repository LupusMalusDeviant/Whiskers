# Components/Shared

Reusable UI widgets used across multiple pages.

## Files

| File | Purpose |
|---|---|
| `ResourceGauge.razor` | A progress bar that changes colour at thresholds (CPU/RAM/disk usage). |
| `HealthBadge.razor` | A small status badge rendering a container's health state. |
| `LogViewer.razor` | A scrolling log display component. |
| `SecretTextField.razor` | R1-30: an editor field for a credential kept in the vault: never shows the stored value; empty keeps it, a new value replaces it, the delete icon removes it with the next save. |
| `LocalAccountsPanel.razor` | R1-49: Settings panel *Local accounts* (Admin only — it checks the role again). States the MFA posture (no MFA for local accounts in 1.0; production uses the IdP with MFA). Lists the local accounts (role, state: active / locked / waiting for a new password / no credential), adds one with a role (`account.create`), resets another one's password (`account.password_reset`) and deletes one after an inline confirmation (`account.delete`) — each through the Mutation Gateway with the email (and role) as the only arguments. A new account and a reset produce a one-time recovery code, shown once in the panel until dismissed or the next action, never stored or recorded. The own row has no reset or delete. |
| `IdentityBindingsPanel.razor` | R1-27: Settings panel *Sign-in identities* (Admin only — it checks the role again). Lists the identity bindings (account, provider, issuer, subject fingerprint — never the raw subject —, how and when bound, last sign-in day) and the pending requests (account, provider, issuer, fingerprint, why pending, whether the provider asserted `email_verified`, expiry). *Confirm* (`identity.binding_confirm`) and *Remove* (`identity.binding_remove`, after an inline confirmation) run through the Mutation Gateway with the id as the only argument; refusals (`last_admin`, `auth_disabled`, store unavailable, …) are shown as messages. With `AUTH_DISABLED` the panel says the writes are refused. |
| `QuietHoursPanel.razor` | R1-56: Settings panel *Quiet hours* (Admin only — it checks the role again). Lists the rules (window, zone, event types, an on/off switch, delete), adds one (name, IANA zone — the server's own zone suggested —, `HH:mm` start and end, event types from `NotificationEventTypes.SuppressibleEvents` plus `log_alert`; none = all), and names what is never held. Saving runs `IQuietHoursService.SaveAsync` through the Mutation Gateway as `config.save` (R1-11, audited); an invalid rule is refused with its reason and changes nothing. |
| `DiskHealthPanel.razor` | R1-58: Settings panel *Disk health (SMART, RAID, ZFS)* (Admin only — it checks the role again): one switch, off by default, and a link to `docs/operations/disk-health.md`. Switching runs `IDiskHealthSettingsService.SaveAsync` through the Mutation Gateway as `config.save` (R1-11, audited); a refused or failed save shows the setting unchanged. |
| `DiskHealthBlock.razor` | R1-58: the *Disks* block in a server's expanded panel on the dashboard — the overall state and one line per disk, md array and ZFS pool (state, name, reason, age of the SMART data or "live"), from `IDiskHealthService`. Read-only, for every signed-in role; nothing is shown while the feature is off. Names and reasons come from the host and are rendered as text. |
| `MetricRetentionPanel.razor` | R1-55: Settings panel *Metric retention* (Admin only — it checks the role again). One field per tier (raw, 10 min, 1 h, 8 h) and the alert history; a value set by the environment or `appsettings.json` is disabled and names its source. Saving runs `IMetricRetentionService.SaveAsync` through the Mutation Gateway as `config.save` (R1-11, audited). |
| `OutboundExceptionsPanel.razor` | R1-54 (INV-60): Settings panel *Notification targets* (shown with the Notifications module, Admin only — it checks the role again). Lists each configured channel the outbound guard refuses, with the refused address or *unresolved* — scheme, host and port only, never a URL path or query — and edits the exact exceptions (IP plus port, or name plus port plus addresses); saving runs `IOutboundExceptionService.SaveAsync` through the Mutation Gateway as `config.save` (R1-11, audited). |
| `RegistriesPanel.razor` | Settings panel for container registries (F8): save/delete run through the Mutation Gateway as `registry.save` / `registry.delete` (Admin, R1-11); the credential goes to the vault and is never a gateway argument. |
| `RoleGuard.razor` | Renders its child content only if the current user holds the required role. |
| `AiChat.razor` | The site-wide floating chat widget. A **hybrid**: a read-only advisor (see [`../../Services/AiChat/`](../../Services/AiChat/)) while the agent is disabled; when `Agent.Enabled`, it becomes the **acting agent** (tools + guardrails) and feeds the current page's context (route + visible text via `swAgent.getPageContext`), plus an optional screenshot (html2canvas > vision model), into each turn. Confirmations route through the central approvals (bell + Approvals page), decided as the signed-in user at their current role; closing or clearing the chat, or a dropped connection, ends its run and cancels its pending approvals (`AgentChatLifetime`, R1-15); the conversation stays, the next message starts a new run. |
| `ChatWidget.razor` | Renders a curated rich widget embedded in an agent reply, a live CPU/RAM ApexChart or a status card for a server/container. Driven by a [`ChatWidgetSpec`](../../Models/Agent/ChatWidget.cs) parsed from a `[[chart:…]]` / `[[status:…]]` token (see [`../../Services/Agent/Chat/`](../../Services/Agent/Chat/)); data via `IMetricsQueryService`. |
| `NotificationBell.razor` | AppBar bell + unread badge + dropdown feed of recent events, with a toast on arrival. Each entry is clickable and navigates to the relevant page via its `Link` (approval > Freigaben, agent run > Agent-History, CVE > CVEs, log alert > Logs, container event > that container); entries without a target stay non-clickable. See [`../../Services/Notifications/InAppNotificationStore.cs`](../../Services/Notifications/InAppNotificationStore.cs). |
| `LanguageSwitcher.razor` | AppBar language menu (F2 i18n) — navigates through the anonymous `/set-culture` endpoint to set the culture cookie. |
| `AutomationOwnersPanel.razor` | Settings panel "Automation owners" (PC-D6): shows who AutoPatch, AutoUpdate and the VPN bring-up at start run as and lets an Admin take them over (`automation.owner_set` through the gateway, stored in `IAutomationOwnerStore`). AutoPatch and the VPN bring-up do not run without an owner. For the VPN bring-up it also shows how it ended at this start (`IVpnBootstrapState`, R1-43) and that a takeover takes effect at the next start. |
| `SelfBackupPanel.razor` | Settings panel for F3 self-backup & restore (manual backup download, restore upload, schedule hint). |
| `ProductionReadinessPanel.razor` | W3.4: the static "Produktionsreif?" checklist (auth, vault, backup schedule, update policy, non-root, HTTPS) from [`IProductionReadinessService`](../../Services/Setup/ProductionReadinessService.cs). |
