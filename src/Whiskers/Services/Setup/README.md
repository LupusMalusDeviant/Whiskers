# Services/Setup

First-run and operational-readiness state, consumed by the setup wizard (W1) and the Settings page.

## Files

| File | Purpose |
|---|---|
| `ISetupStateService.cs` / `SetupStateService.cs` | Whether setup is complete (= at least one admin exists; admin-role-authoritative with a cached flag file). Drives the setup-redirect middleware. R1-48 (designed exemption from the gateway, maintainer option a): completion records `setup.first_admin` in the audit log **before** it writes anything and refuses without that record; it then adds the address to the whitelist (`AddFirstAdminAsync`) and makes it Admin (`SetFirstAdminAsync`), both closed once any Admin exists, both under one held `AccessControlWriteGate` (the write boundary of all role and whitelist writers, review round 2). Whitelist first: a crash in between leaves setup open with the same token. |
| `SetupCompletion.cs` | The atomic, race-guarded wizard completion (create admin → mark complete). |
| `ProductionReadinessService.cs` | Contract 0011 (INV-56): every line has a stable, untranslated id (`ReadinessCheck.Id`; the list is `ProductionReadinessService.Ids`: `auth`, `self-exposure`, `vault`, `guardrail-policy`, `cloud-dns`, `notify-ai`, `stored-encrypted`, `self-backup`, `pg-tools`, `update-policy`, `stores-readable`, `non-root`, `https`, `oidc-https`, `proxy-trusted`, `mtls-proxy`, `mtls-shared-live`, `mtls-allow-cn`, `mtls-identity` (one per host), `mtls-shared-key`, `mtls-keys-protected`, `keys-sealed`, `vault-rotation`); tests and `docs/v1/CLAIMS.md` find lines by id. Titles, details and link texts are the `Readiness_<id in camelCase>_<variant>` keys of `Resources/SharedResource.resx` (English) and `SharedResource.de.resx` (German), resolved at call time in the caller's UI culture through `IStringLocalizer<SharedResource>` (without one: the real resources); each key is a whole sentence, values inserted through `{0}` are data and stay untranslated, dates are `yyyy-MM-dd`. `ReadinessLocalizationTests` holds both languages to the same keys, placeholders and fact tokens and runs every branch with a key-echo localizer. Test seams (`internal init`): `PgDumpVersion`, `RecoveredStores`, `IsPrivileged`. Contract 0010: the line "Guardrail policy loaded and recorded" (`guardrail-policy`, `GuardrailPolicyCheck`) is red while the guardrails are fail-closed (with the store's reason), while the database's record that a policy exists could not be written (`MarkerProblem`) or is not confirmed yet. W3.4: the static "production ready?" checklist shown in Settings — read-only checks (auth on, VAULT_KEY set, self-backup scheduled, update policy, non-root, HTTPS). Informational only, gates nothing. R1-29 (INV-56): it reports where the cloud API keys and the DNS token actually are (plaintext counted from servers.json and app-settings.json, not inferred from the vault switch), and the vault line names which credentials are still unencrypted (since R1-30: inbound webhook secrets, SSH and mTLS keys). R1-30: a second credentials line names each notification/AI credential still stored in plaintext (app-settings.json, agent-settings.json). R1-31: a third line counts plaintext webhook secrets and rollback snapshots in the database and plaintext data-protection key files; the vault line names the SSH and mTLS client keys as the only plaintext left. R1-35: "Data stores readable" (`stores-readable`) names the JSON stores recovered from their previous generation since the start and the unreadable copies (`*.corrupt-*`, `guardrails.json.unreadable-*`) still in the data directory. R1-33: on PostgreSQL a line shows whether the client tools for the self-backup are usable (`pg_dump --version`; a found version is kept for the process); tools without the `\restrict` protection (before 17.6, 16.10, 15.14, 14.19) are flagged, since their backups cannot be restored. Contract 0006: with `Auth:Disabled` a line reads Whiskers' own container on its own host (`LogMonitorService.ResolveSelfServerIds`, the names of `WHISKERS_SELF_CONTAINERS`): a label with an exposure prefix is not OK ("Whiskers itself is published through `<label>` with sign-in turned off", the key only); a container that cannot be found or read is "unknown", not OK; otherwise no line. |
