# Services/Backup

Two kinds of backup live here: **Whiskers' own self-backup and restore** of its data directory and database (F3: `BackupService`, the archive format and cipher, the deferred restore at the next start — operator guide: [`docs/operations/backup-and-recovery.md`](../../../../docs/operations/backup-and-recovery.md)), and Docker **volume backups** of managed containers, written to `/app/data/backups` on the target host as `tar.gz` archives with metadata rows in the database.

**Restore safety (2026-07):** `RestoreVolumeAsync` no longer wipes the target volume before it has verified the restore can succeed. The sequence is now: (1) verify the archive exists and is an intact gzip tar (`tar tzf` in a read-only alpine container) and abort untouched if not; (2) take an automatic pre-restore safety backup of the current volume so the wipe is reversible; (3) clear the volume (including dotfiles, via `find /data -mindepth 1 -delete`) and extract. A missing/corrupt archive can no longer destroy the live volume.

| `RestoreCli.cs` | R1-34: `--restore-backup <id>` (also `--restore-backup=<id>`; or `latest-pre-upgrade`: the backup of the unfinished upgrade, else the newest pre-upgrade backup), optionally `--for-previous-release` — recovery without a running UI. | `PostgresDumpTool.cs` | R1-33: runs the PostgreSQL client tools for the self-backup. `pg_dump --format=custom --no-owner --no-acl --schema=public` writes `database.pgdump` into the archive (format 2; SQLite archives stay format 1), owner-only; a dump without both migration-history tables in `public` fails the backup (Whiskers' tables are elsewhere, e.g. through a search path). A restore pipes `pg_restore` into `psql ON_ERROR_STOP` — the script never lands on disk — between `BEGIN; DROP SCHEMA public CASCADE; CREATE SCHEMA public;` and `COMMIT`; the script runs only when it opens with `\restrict` (client 17.6+, no psql meta-commands from a crafted dump). The transaction id is kept in a psql variable before the script (which `\restrict` keeps from changing it) and compared after it: a script that ends the transaction on its own is refused and nothing more is committed; the dump's `statement_timeout = 0` is replaced by the tool time limit. The dry run that `BackupService` performs before the commit marker (after the pre-restore safety backup) ends with `ROLLBACK` and, before it, checks the migration histories against the manifest, runs the start's migrations (idempotent script) and reads every mapped column. When psql stops early, `pg_restore` is stopped too, so the error is reported at once. The time limit and a cancellation kill both tools at once (a script that keeps psql from reading cannot hold the pipe), and every tool stream is read with a 16 Mi character bound. The connection goes through the libpq environment (channel binding mapped, `Options` refused; inherited `PG*` variables removed except those Npgsql would use too when the connection string has no value — `PGPASSWORD`, `PGUSER`, `PGSSLCERT`, `PGSSLKEY`, `PGSSLROOTCERT`, `PGTARGETSESSIONATTRS` — and `PGPASSFILE`, an inherited `PGOPTIONS` refused; VerifyFull without a root certificate uses `system`, VerifyCA the system bundle file; one host only, a bare IPv6 address allowed); only the error lines of the tools' output are kept, quoted values left out, then redacted. `RestoreBootHandler` restores the dump at the start, before the files are swapped, reading the database settings with the data directory's JSON layers like the app; a start not configured for PostgreSQL stops instead. Code objects (functions, triggers, rules, views, policies, operators) left in `public` after the script, and anything created or changed outside `public` (a digest of `pg_db_role_setting` and of the schemas, relations, functions, triggers, rules, policies and operators of every other non-system schema, taken after `public` is replaced and compared after the script), are refused, as are grants, unlogged or foreign tables in `public`, default privileges and publications; success needs a random marker that psql prints after the checks and the `COMMIT` (exit code 0 alone is not proof: a script ending in an open `COPY` would swallow the tail), and a script ending inside a COPY block is refused; `Require Auth` maps to `PGREQUIREAUTH`; the rewrites of `SET`/`CREATE SCHEMA` lines skip COPY data. The dump is UTF-8 (`--encoding=UTF8`), read strictly, script lines capped at 64 Mi characters. Tools from the environment variable `WHISKERS_PG_BIN_DIR` only (set in the image; never from the data directory's settings files), otherwise `PATH`; time limit `WHISKERS_PG_TIMEOUT_MINUTES` (environment only, default 30). A PostgreSQL archive without the dump (made before R1-33) is refused and listed as *files only* (`SelfBackupInfo.Restorable`). Procedure: `docs/operations/backup-and-recovery.md`. |

R1-58: `disk-health.json` (the last disk-health readings and open disk-health alerts) is local for the same reason. |
| `TarHeaderScreen.cs` | R1-32: reads the tar structure as it passes to `TarReader` and refuses a header before the reader acts on it — entry types other than file and directory, data on a directory, and PAX records or GNU long names above 1 MiB (the reader allocates their declared size before reading). | `StagedRestoreValidator.cs` | R1-32: checks the extracted restore before the commit marker — SQLite `integrity_check`, the migration history equal to the manifest, no triggers or views, no tables the start would create again (a history-less database only when the start baselines it: `DatabaseInitializer.SentinelTable`), every JSON store a service reads at start deserializes as its type (the two configuration layers hold an object, the rest parses), every data-protection key file is XML. |
| `BackupArchiver.cs` / `BackupArchiveCipher.cs` / `SelfBackupManifest.cs` / `SelfBackupInfo.cs` | The self-backup archive (tar.gz), its VAULT_KEY-derived encryption and its manifest. R1-32: inspect and extract refuse forbidden, duplicate (case-insensitive), file/directory-conflicting and non-canonical (`a/../b`, `a//b`) entries and archives above `BackupExtractionLimits` (100k entries, 32 GiB, 256 MiB per JSON store, 1 MiB for the manifest, 1 MiB of headers per entry, 1 MiB per data-protection key file and 500 files / 64 MiB for the key ring, names at most 4096 characters and 32 levels deep and 64 Mi characters together, the decompressed stream bounded too; backslashes in names refused; only `keys/*.xml` of the key ring), skip entries that are not restore targets and create every file owner-only. ## Wiring

This is the opt-in **VolumeBackups module** ([`../../Modules/VolumeBackups/`](../../Modules/VolumeBackups/),
toggle `Features:volumebackups:Enabled`): its `ConfigureServices` registers `IVolumeBackupService` and owns the
`backups` nav entry. The Scheduler module's `TaskExecutor` consumes this service, so Core keeps the
`NoopVolumeBackupService` default above for when the module is off.
