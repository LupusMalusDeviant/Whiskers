# Services/Docker

Everything that talks to the Docker Engine. This folder owns the **connection layer** (how Whiskers reaches each host's Docker daemon, local socket, SSH tunnel, or TCP/mTLS) and the **operations layer** (containers, images, networks, stats).

Connections are established per configured server and cached; for SSH-tunnelled hosts the manager self-heals dead tunnels. For TCP/mTLS hosts there is no SSH at all (see [docs/ARCHITECTURE.md](../../../../docs/ARCHITECTURE.md)).

## Files

| File | Purpose |
|---|---|
| `NetworkVerifiers.cs` | R1-37 (INV-43): networks listed again after the call — created with the requested driver, removed, a container attached or detached. `ComposeDeployVerifier`: every container of the project the plan resolved (reported through `MutationScope.ReadBack`, else the named project) runs or exited 0 — matched on the `com.docker.compose.project` label itself and limited to the services the deployed files define, so an orphan of a removed service does not count; an interpolated or non-label project name, or none, is `NotVerifiable`. |
| `IDockerService.cs` / `DockerService.cs` | The main Docker operations surface: list/inspect/start/stop/restart/remove containers, images, networks, stats, logs. `DockerService` is a thin **facade** — every member delegates to an internal collaborator class in [`Operations/`](Operations/) (containers, lifecycle/rollback, images, networks, host shell, system info), which the facade constructs itself (no extra DI registrations). Also runs **host shell commands SSH-free** via a one-shot privileged `nsenter` container over the mTLS Docker channel. Each such helper is labelled `serverwatch.hostshell=1` and removed in a `finally`; if a run is interrupted before that (app rebuilt mid-command, mTLS drop) the next call sweeps any leftover labelled, non-running helpers older than 30 s, so they never pile up. R1-41: `ListAllContainersAsync(all, ct)`, `ListAllContainersDetailedAsync(all, ct)`, `InspectContainerStateAsync(…, ct)`, `GetConfiguredImageAsync(…, ct)`, `GetImageDigestAsync(…, ct)` and `GetImageContractAsync(imageRef, serverId, ct)` take the caller's token (a loop's stop, a closed chat) and pass it to the request and the wait for a slot; a cancelled caller gets an `OperationCanceledException`, never a listing that looks like silent servers or a `null` that reads as "could not inspect" (a background duplicate is still dropped by the budget's single-flight and answers `null`). The interface defaults of these overloads only stop waiting; `DockerService` cancels the work. The per-server `ListContainersAsync(all, serverId, ct)` treats `ct` as the caller's own token the same way, and `GetContainerLogsAsync(…, deadline, callerToken)` keeps the log monitor's fetch timeout (a server deadline: it bounds the request and the waits, and an expiry at the host counts against the server) apart from its stop (never held against the server). The fleet listing gives each server 8 s (`ContainerOperations.PerServerTimeout`) for the whole call — the wait for its client and for a budget slot as well as the request; running out is that server's timeout (reported in `FailedServers`), never the caller's cancellation. `IDockerConnectionManager.ExecuteAsync`/`ExecuteGuardedAsync` take a `callerToken` — it ends the wait for the client and for a budget slot, and a call it cancelled is neither retried, nor held against the server by the circuit breaker, nor reported as budget saturation (`ServerBudget`) — and a `deadline` about the server, which bounds the same waits: running out in the queue is `BudgetSaturatedException` (not counted by the circuit), while waiting for the client an `OperationCanceledException`. Contract 0006: `DisableRestartAsync` (`container.disable_restart`, `docker update --restart=no`) only ever composed by the compose capabilities, so a container a run created with an undecided exposure stays stopped; like start/stop it takes a bare client (the circuit breaker must not refuse it). R1-48: `IDockerService` is `[OmittedServer]` — an omitted `serverId` is the configured default server, as `DockerConnectionManager.GetClientAsync` routes it; the scope guard matches it the same way. |
| `ContainerVerifiers.cs` | R1-36 (INV-43): the gateway's read-backs of the container capabilities — start/restart/update/rollback must leave the container running (not OOM-killed; a start or restart of a one-shot container that exited 0 also counts), stop must leave it exited/created/dead, remove must leave it gone. An update reads the container the call returned (through a tool: the container of the same name); `app.deploy` is read back by the compose verifier since contract 0013 (`NetworkVerifiers.cs`); a rollback named only by its snapshot id is `NotVerifiable`. The docker service is resolved per verification (it is guarded by the gateway that holds the verifiers); a read the server budget turned away is tried again. |
| `Operations/` | The internal collaborator classes behind the `DockerService` facade — one file per concern; see [`Operations/README.md`](Operations/README.md). |
| `Budget/` | The **per-server load cap** every Docker call passes through, so the sum of what all the loops do against one host is bounded — the thing that was missing on 2026-08-26. Separate lanes for background work and for anything a human is waiting for; see [`Budget/README.md`](Budget/README.md). |
| `IDockerConnectionManager.cs` / `DockerConnectionManager.cs` | Provides and caches a `DockerClient` per server, with self-healing reconnect for dead SSH tunnels (instance-aware invalidation, so a retry never tears down a client another caller just rebuilt). Also builds each client (local / SSH-tunnel / TCP+mTLS transport, client certs + CA trust for mTLS); for TCP/mTLS it validates the server certificate's **chain and hostname** (`ValidateMtlsServerCert`) so a valid-but-wrong cert can't impersonate the host. Contract 0015: the client key is read through `IMtlsClientKeyLoader` (sealed `f1:` key opened with the vault key, never a plaintext fallback); a key that does not open fails the connection closed. SSH-tunnelled hosts get their key as a short-lived `ISshKeyLeases` lease. |
| `ISshTunnelManager.cs` / `SshTunnelManager.cs` | Manages local SSH tunnels to remote Docker hosts. The local end is a Unix socket per attempt in a private directory with a random name (created 0700 by `mkdtemp`, removed on dispose) and the socket itself owner-only (`-o StreamLocalBindMask=0177`), so no other local process can reach the remote docker.sock (Fable review); only on Windows is it a free loopback port, picked with a bind-race retry. It waits until the forward actually accepts connections and drains the ssh stderr so a full pipe can't freeze the tunnel. R1-42: the tunnel's ssh arguments (`BuildTunnelArguments`) check user, host and port with `CommandOperands` and end with `--` and the destination; an unsafe value starts no process. |
| `HelperImages.cs` | The images Whiskers starts as its own helpers on managed hosts (host shell, volume backup/restore): `alpine:3.22`, pinned by digest, so a moved tag or another image tagged `alpine` never runs with the host's root (Fable review H5). `HelperImagePinningTests` refuses an unpinned alpine anywhere in the app. |
