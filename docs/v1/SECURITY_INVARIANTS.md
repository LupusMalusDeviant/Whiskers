An invariant is a property that must hold on **every** path, for **every** principal, at **every** point in time.
Each one has a stable ID, a statement that a test can decide, its current status, and the test that will pin it.
The [`PRODUCT_CONTRACT.md`](PRODUCT_CONTRACT.md) path matrix refers to these IDs.

**Release rule.** v1.0 ships only when every invariant below is ✅ and its named test exists and passes. A
deliberate exception needs a recorded decision in [`PRODUCT_CONTRACT.md` §6.1](PRODUCT_CONTRACT.md#61-release-decisions)
and a matching limitation in the product documentation. The release gate (contract 0008, `ReleaseGateTests`, read
[`RELEASE_GATE.md`](RELEASE_GATE.md)) checks this table mechanically, so keep its format: one row per invariant, the
ID in the first column, the status cell **one bare symbol** (✅, ⚠️, ❌ or ❓ — a qualification goes into the evidence
column), every invariant that is not ✅ listed under *Open invariants* in `RELEASE_GATE.md`, and §11's counts equal to
the table's. A new invariant raises the pinned highest ID there; a removed one is retired there, never deleted.

**Status legend.** ✅ holds on every path and is pinned by a test · ⚠️ holds on some paths, or holds but is untested ·
❌ violated · ❓ not verified yet.

**Test column.** An existing test is named as `Class.Method`, or as `Class` for every test of that class. A planned
test is named as `Class.Method` *(planned, WPx)*, or `Class` *(planned, WPx)* for a class that does not exist yet.
Backticks in this column are for test names only; prose stands outside them. A planned entry names the test that is
still owed: a method or class that does not exist yet (the gate fails a planned name that already exists). A `|`
inside a cell, also inside backticks, is written `\|`.
"Wire test" means a test through `WebApplicationFactory<Program>` in `[Collection("WebAppBoot")]`.
