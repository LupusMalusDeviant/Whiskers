# Whiskers 1.0.0

Whiskers is a self-hosted control plane for Docker hosts: a dashboard, an MCP server and an agent that acts under
guardrails. 1.0 is the first release whose security claims are each backed by named tests that CI requires.

## What 1.0 means

- **One gateway for every change.** The UI, MCP tools, the agent, webhooks, scheduled tasks, AutoUpdate and AutoPatch
  all go through the Mutation Gateway. For each change it:
  - resolves the target;
  - decides who acts (a structured principal, never a display name);
  - asks for approval where the policy requires it;
  - re-reads the target right before acting, so a target that vanished or changed in between is refused;
  - writes exactly one audit event per attempt.
- **Fail closed.** These are refused, not allowed:
  - a broken guardrail policy;
  - an unknown MCP permission level;
  - a target that cannot be resolved;
  - an audit log that cannot be written.
- **Root-equivalent actions need Admin on every path.** This covers container shells, arbitrary SQL, deployments and
  firewall rules.
- **Secrets at rest are sealed.**
  - SSH keys and mTLS client keys are sealed with the vault key.
  - MCP keys are stored only as a hash.
  - The vault key can be rotated, and the rotation is audited.
- **Every managed host can get its own mTLS client identity.** A stolen key no longer opens the whole fleet.
- **Compose deployments start exactly the images that were inspected** (pinned by image ID). A change that exposes a
  port, proxy or tunnel is decided as an exposure.
- **MCP 2.4.** Sessions are bound to the key that opened them.
- **Release gate.**
  - `docs/v1/SECURITY_INVARIANTS.md` lists 62 invariants, and each one names its tests.
  - CI runs those tests method by method, and a release cannot be tagged while one is open.
  - Open now: INV-58 (#184), which holds per host after that host's migration.

## Upgrading from 0.15.0

Read **Upgrading from 0.15.0** in [CHANGELOG.md](../../CHANGELOG.md) before you update. In short:

1. Set `VAULT_KEY_FILE` (or `VAULT_KEY`) and keep a copy outside the data directory.
2. Let the first start finish. It writes a self-backup first, which can take minutes with a large metrics database.
3. Everyone signs in again once. A generic OIDC provider needs its first sign-in confirmed, unless you set
   `Oidc__TrustEmailVerified=true`.
4. Behind a reverse proxy that is not on loopback, set `ForwardedHeaders__TrustedNetworks__0`.
5. MCP clients reconnect once. A gateway that pins tool definitions holds back the changed tools until you accept them.
6. Take over the old webhooks and Git deploy apps (Owner column).
7. Migrate each host to its own mTLS identity, then retire the shared client key.
8. Kubernetes: apply `deploy/k8s/whiskers-agent-rbac.yaml` again.

## Install

```bash
VER=1.0.0
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/install.sh"
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/checksums.txt"
sha256sum --check --ignore-missing checksums.txt && bash install.sh
```

The image `ghcr.io/lupusmalusdeviant/whiskers:1.0.0` is built for amd64 and arm64. It is Trivy-gated, has an SBOM and
provenance, and carries a keyless cosign signature. See `docs/installation.md` for the signature check and the other
ways to install.
