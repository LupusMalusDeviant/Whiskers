# Whiskers 1.0.0

> **Draft.** These notes are for the coming 1.0.0 and not yet released. v1.0.0 and v1.0.1 were published on
> 2026-11-14/16 and withdrawn on 2026-11-16; their content ships with this 1.0.0.

Whiskers is a self-hosted control plane for Docker hosts: a dashboard, an MCP server and an agent that acts under
guardrails. 1.0 is the first release whose security claims are each backed by named tests that CI requires.

## What 1.0 means

- **One gateway for every change.** The UI, MCP tools, the agent, webhooks, scheduled tasks, AutoUpdate and AutoPatch
  all go through the Mutation Gateway. For each change it:
  - resolves the target;
  - decides who acts (a structured principal, never a display name);
  - asks for approval where the policy requires it;
  - re-reads the target right before acting, so a target that vanished or changed in between is refused;
  - writes exactly one audit event per attempt.
- **Fail closed.** These are refused, not allowed:
  - a broken guardrail policy;
  - an unknown MCP permission level;
  - a target that cannot be resolved;
  - an audit log that cannot be written.
- **Root-equivalent actions need Admin on every path.** This covers container shells, arbitrary SQL, deployments and
  firewall rules.
- **Secrets at rest are sealed.**
  - SSH keys and mTLS client keys are sealed with the vault key.
  - MCP keys are stored only as a hash.
  - The vault key can be rotated, and the rotation is audited.
- **Every managed host can get its own mTLS client identity.** Once a host is migrated, a stolen key of another
  host no longer opens it.
- **Compose deployments start exactly the images that were inspected** (pinned by image ID). A change that exposes a
  port, proxy or tunnel is decided as an exposure.
- **MCP 2.4.** Sessions are bound to the key that opened them.
- **Release gate.**
  - `docs/v1/SECURITY_INVARIANTS.md` lists 62 invariants, and each one names its tests.
  - CI runs those tests method by method, and a release cannot be tagged while one is open, unless an accepted
    exception covers it.
  - One invariant ships at ⚠️ under the accepted exception RG-1: INV-58 (#184) holds per host only after that host's
    migration. A host still on the shared client key is exposed as before (see
    `docs/operations/per-host-mtls-migration.md`).

## Security fixes from the review

A full review of the withdrawn 1.0.0 reproduced 98 findings, most with a failing test. The security fixes and the crash
fixes are part of this release; the rest is planned for 1.1.0. Contract 0017
(`docs/contracts/0017-release-1-0-1-security-fixes.md`) defines the security fixes.

- **Approval requests always reach the channels.** A second request inside the throttle window is no longer dropped.
- **mTLS.** The host's CSR is checked and re-encoded before it reaches the CA host, and every SAN is counted.
- **Agent chat and CSP.** Model output is rendered with an explicit Markdown pipeline and a stricter sanitizer. The
  CSP sets `script-src 'self'`, and no inline script or `eval` interop is left.
- **Compose.** `use_api_socket` counts as a Docker-socket mount, and a privileged hook needs approval.
- **Whitelist.** The seeded local admin and new local accounts can sign in while the OAuth whitelist is enabled.
- **Redaction.** Every sink column is redacted or exempt with a reason, and an `Authorization` value is redacted
  whole. Container env and the UI share one masking rule.
- **Guardrails.** `execute_command` reads mount sources, quoting, braces and globs as the shell does before it allows
  a command near the control plane.

## Fixes

- The telemetry compose files need `TS_IP` and no longer bind to every interface.
- A failed container update or rollback restores the previous container.
- No Python is left in the project: onboarding, borg-fleet and tailnet-guard use `sh`, `jq` and `sqlite3`.
- Tailscale starts when `VPN_HOSTNAME` is empty.
- The database tool reads PostgreSQL, MySQL/MariaDB and Redis output correctly.
- Restores replace the database the app actually opens; volume backups clean up after themselves.
- Errors in the UI no longer end the Blazor connection.

The full list is in [CHANGELOG.md](../../CHANGELOG.md).

## Upgrading from 0.15.0

Read **Upgrading from 0.15.0** in [CHANGELOG.md](../../CHANGELOG.md) before you update. In short:

1. Set `VAULT_KEY_FILE` (or `VAULT_KEY`) and keep a copy outside the data directory.
2. Let the first start finish. It writes a self-backup first, which takes about a minute with a large metrics
   database on a spinning disk.
3. Everyone signs in again once. A generic OIDC provider needs its first sign-in confirmed, unless you set
   `Oidc__TrustEmailVerified=true`.
4. Behind a reverse proxy that is not on loopback, set `ForwardedHeaders__TrustedNetworks__0`.
5. MCP clients reconnect once. A gateway that pins tool definitions holds back the changed tools until you accept them.
6. Take over the old webhooks and Git deploy apps (Owner column).
7. Migrate each host to its own mTLS identity, then retire the shared client key.
8. Kubernetes: apply `deploy/k8s/whiskers-agent-rbac.yaml` again.
9. Hardened profile: take the new `docker-compose.hardened.yml` (the socket proxy now listens on a Unix socket, not
   on `127.0.0.1:2375`). A server stored on the old port without TLS is moved at the first start. If it was a TCP
   server, nothing that runs on the host works for it any more (among them deploy, `.env`, `execute_command`,
   firewall, nginx, volume backups and CVE scans).
10. mTLS proxy certificates: renewal now works only for a certificate the fleet CA issued for the address Whiskers
    connects to; renew any other by hand.
11. With the OAuth whitelist enabled, add `WHISKERS_ADMIN_EMAIL` to it by hand.
12. Rotate the Basic credentials that an earlier version stored or logged as `Authorization=*** <credential>`.
13. In the UI, `PWD`-like environment variables are now masked.
14. borg-fleet: install `jq` on the Whiskers host and `sqlite3` on each fleet host, then run `borg-enroll` again.
15. Install `jq` wherever tailnet-guard runs.
16. A reverse proxy that injects inline scripts is blocked by the new CSP.

## Install

```bash
VER=1.0.0
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/install.sh"
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/checksums.txt"
sha256sum --check --ignore-missing checksums.txt && bash install.sh
```

The image `ghcr.io/lupusmalusdeviant/whiskers:1.0.0` is built for amd64 and arm64. It is Trivy-gated, has an SBOM and
provenance, and carries a keyless cosign signature. See `docs/installation.md` for the signature check and the other
ways to install.
