# Whiskers 1.0.0

Whiskers ist eine selbst gehostete Steuerzentrale für Docker-Hosts. Es besteht aus einem Dashboard, einem MCP-Server
und einem Agenten, der unter Leitplanken handelt. 1.0 ist das erste Release, in dem jede Sicherheitsaussage durch
benannte Tests belegt ist, die die CI verlangt.

## Was 1.0 bedeutet

- **Ein Tor für jede Änderung.** UI, MCP-Tools, Agent, Webhooks, geplante Aufgaben, AutoUpdate und AutoPatch laufen
  alle durch das Mutation Gateway. Für jede Änderung:
  - löst es das Ziel auf;
  - entscheidet es, wer handelt (ein strukturierter Principal, nie ein Anzeigename);
  - holt es eine Freigabe ein, wo die Policy das verlangt;
  - liest es das Ziel direkt vor der Ausführung erneut; ist es inzwischen weg oder verändert, wird abgelehnt;
  - schreibt es genau ein Audit-Ereignis pro Versuch.
- **Im Zweifel geschlossen.** Diese Fälle werden abgelehnt, nicht durchgelassen:
  - eine kaputte Guardrail-Policy;
  - eine unbekannte MCP-Berechtigungsstufe;
  - ein Ziel, das sich nicht auflösen lässt;
  - ein Audit-Log, das sich nicht schreiben lässt.
- **Root-gleiche Aktionen brauchen auf jedem Weg Admin.** Das gilt für Container-Shells, freies SQL, Deployments und
  Firewall-Regeln.
- **Geheimnisse liegen versiegelt auf der Platte.**
  - SSH-Schlüssel und mTLS-Client-Schlüssel sind mit dem Vault-Key versiegelt.
  - MCP-Schlüssel liegen nur als Hash vor.
  - Der Vault-Key lässt sich wechseln; der Wechsel wird protokolliert.
- **Jeder verwaltete Host kann eine eigene mTLS-Client-Identität bekommen.** Ein gestohlener Schlüssel öffnet nicht mehr
  die ganze Flotte.
- **Compose-Deployments starten genau die geprüften Images**, festgehalten über die Image-ID. Wer einen Port, einen
  Proxy oder einen Tunnel öffnet, wird als Freigabe einer Erreichbarkeit entschieden.
- **MCP 2.4.** Sitzungen sind an den Schlüssel gebunden, der sie geöffnet hat.
- **Release-Gate.**
  - `docs/v1/SECURITY_INVARIANTS.md` führt 62 Invarianten, jede mit ihren Tests.
  - Die CI verlangt diese Tests einzeln, und ein Release lässt sich nicht taggen, solange eine offen ist.
  - Offen ist derzeit INV-58 (#184). Sie gilt je Host, sobald der Host umgestellt ist.

## Update von 0.15.0

Vor dem Update den Abschnitt **Upgrading from 0.15.0** in der [CHANGELOG.md](../../CHANGELOG.md) lesen. Kurz:

1. `VAULT_KEY_FILE` (oder `VAULT_KEY`) setzen und eine Kopie außerhalb des Datenverzeichnisses aufbewahren.
2. Den ersten Start durchlaufen lassen. Er schreibt zuerst eine Selbstsicherung; bei einer großen Metrik-Datenbank
   auf einer drehenden Platte dauert das etwa eine Minute.
3. Alle melden sich einmal neu an. Bei einem allgemeinen OIDC-Anbieter muss die erste Anmeldung bestätigt werden, außer
   `Oidc__TrustEmailVerified=true` ist gesetzt.
4. Hinter einem Reverse-Proxy, der nicht auf Loopback läuft, `ForwardedHeaders__TrustedNetworks__0` setzen.
5. MCP-Clients verbinden sich einmal neu. Ein Gateway, das Tool-Definitionen festhält, gibt geänderte Tools erst nach
   Annahme frei.
6. Alte Webhooks und Git-Deploy-Apps übernehmen (Spalte „Owner“).
7. Jeden Host auf eine eigene mTLS-Identität umstellen und danach den gemeinsamen Client-Schlüssel stilllegen.
8. Kubernetes: `deploy/k8s/whiskers-agent-rbac.yaml` erneut anwenden.
9. Gehärtetes Profil: die neue `docker-compose.hardened.yml` übernehmen (der Socket-Proxy hört jetzt auf einem
   Unix-Socket statt auf `127.0.0.1:2375`). Ein Server auf dem alten Port ohne TLS wird beim ersten Start umgestellt.
   War er ein TCP-Server, funktioniert für ihn danach nichts mehr, was auf dem Host läuft (unter anderem Deploy,
   `.env`, `execute_command`, Firewall, nginx, Volume-Backups und CVE-Scans).
10. mTLS-Proxy-Zertifikate: Erneuert wird nur noch ein Zertifikat, das die Flotten-CA für die Adresse ausgestellt hat,
    mit der Whiskers sich verbindet; jedes andere von Hand erneuern.

## Installation

```bash
VER=1.0.0
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/install.sh"
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/checksums.txt"
sha256sum --check --ignore-missing checksums.txt && bash install.sh
```

Das Image `ghcr.io/lupusmalusdeviant/whiskers:1.0.0` gibt es für amd64 und arm64. Trivy prüft es, es hat SBOM und
Provenance und eine schlüssellose cosign-Signatur. Die Signaturprüfung und die anderen Installationswege stehen in
`docs/installation.md`.
