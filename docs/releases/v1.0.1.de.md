# Whiskers 1.0.1

Ein Sicherheits- und Stabilitätsrelease. Eine vollständige Prüfung von 1.0.0 hat 98 Befunde nachgestellt, jeden mit
einem fehlschlagenden Test. Die Sicherheits- und die Absturzkorrekturen kommen mit 1.0.1, der Rest ist für 1.1.0
geplant. Vertrag 0017 (`docs/contracts/0017-release-1-0-1-security-fixes.md`) legt die Sicherheitskorrekturen fest.

## Sicherheit

- **Freigabeanfragen erreichen immer die Kanäle.** Eine zweite Anfrage im Drosselungsfenster geht nicht mehr verloren.
- **mTLS.** Die CSR des Hosts wird geprüft und neu kodiert, bevor sie den CA-Host erreicht, und jeder SAN wird gezählt.
- **Agenten-Chat und CSP.** Modellausgaben laufen durch eine feste Markdown-Pipeline und einen strengeren Sanitizer.
  Die CSP setzt `script-src 'self'`; kein Inline-Skript und kein `eval`-Interop ist übrig.
- **Compose.** `use_api_socket` zählt als Docker-Socket-Mount, und ein privilegierter Hook braucht eine Freigabe.
- **Whitelist.** Der angelegte lokale Admin und neue lokale Konten können sich bei aktiver OAuth-Whitelist anmelden.
- **Schwärzung.** Jede Senken-Spalte wird geschwärzt oder ist mit Grund ausgenommen, und ein `Authorization`-Wert
  wird ganz geschwärzt. Container-Umgebung und UI maskieren nach derselben Regel.
- **Guardrails.** `execute_command` liest Mount-Quellen, Quoting, Klammern und Globs wie die Shell, bevor es einen
  Befehl in der Nähe der Steuerebene zulässt.

## Korrekturen

- Die Telemetrie-Compose-Dateien verlangen `TS_IP` und binden nicht mehr an jede Schnittstelle.
- Ein fehlgeschlagenes Container-Update oder Rollback stellt den vorigen Container wieder her.
- Im Projekt ist kein Python mehr: Onboarding, borg-fleet und tailnet-guard nutzen `sh`, `jq` und `sqlite3`.
- Tailscale startet auch mit leerem `VPN_HOSTNAME`.
- Das Datenbank-Tool liest die Ausgaben von PostgreSQL, MySQL/MariaDB und Redis richtig.
- Eine Wiederherstellung ersetzt die Datenbank, die die App wirklich öffnet; Volume-Backups räumen hinter sich auf.
- Fehler in der UI beenden die Blazor-Verbindung nicht mehr.

Die vollständige Liste steht in der [CHANGELOG.md](../../CHANGELOG.md).

## Update von 1.0.0

Vor dem Update den Abschnitt **Upgrading from 1.0.0** in der [CHANGELOG.md](../../CHANGELOG.md) lesen. Kurz:

1. Bei aktiver OAuth-Whitelist `WHISKERS_ADMIN_EMAIL` von Hand eintragen.
2. Basic-Zugangsdaten wechseln, die 1.0.0 als `Authorization=*** <credential>` gespeichert oder geloggt hat.
3. In der UI werden `PWD`-artige Umgebungsvariablen jetzt maskiert.
4. borg-fleet: `jq` auf dem Whiskers-Host und `sqlite3` auf jedem Flotten-Host installieren, dann `borg-enroll`
   erneut ausführen.
5. `jq` überall installieren, wo tailnet-guard läuft.
6. Ein Reverse-Proxy, der eigene Inline-Skripte einfügt, wird von der neuen CSP blockiert.

INV-58 wird weiter mit ⚠️ unter der angenommenen Ausnahme RG-1 ausgeliefert: Die Invariante gilt je Host erst, wenn
der Host umgestellt ist (siehe `docs/operations/per-host-mtls-migration.md`).

## Installation

```bash
VER=1.0.1
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/install.sh"
curl -fsSLO "https://github.com/LupusMalusDeviant/Whiskers/releases/download/v${VER}/checksums.txt"
sha256sum --check --ignore-missing checksums.txt && bash install.sh
```

Das Image `ghcr.io/lupusmalusdeviant/whiskers:1.0.1` gibt es für amd64 und arm64. Trivy prüft es, es hat SBOM und
Provenance und eine schlüssellose cosign-Signatur. Die Signaturprüfung und die anderen Installationswege stehen in
`docs/installation.md`.
